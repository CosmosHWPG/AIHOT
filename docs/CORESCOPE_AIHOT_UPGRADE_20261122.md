## 适配内容

- 使用上游新版站点、模块注册、公开读接口和分析发布管线。保留 CoreScope 品牌、资源目录、核心网与 AI 的分类和主题。模型榜通过 CoreScope 模块接入网页、公开接口和定时计算。
- 继续使用 CoreScope 来源配置。第一方标记独立于信源等级，后台可继续编辑。正常公开需要领域相关与有效文案，精选还经过新版事件身份与新增价值判定。人工清空分数、填 0 与移除覆盖分别保留明确语义。后台保留密码、可选飞书登录及反向代理会话检查。
- 沿用 Bird 水位和续页、逐源参与方式、公众号缓存、原站正文路由、文章失败缓存、供应商回执、预算开关、近期队列和固定恢复批次。补发和已接收结果复用仍经过原回执及队列。
- Windows 启动最低要求更新为 Node.js 24.22.1，演练使用独立 Node.js 24.22.3。

## 迁移演练

隔离 PostgreSQL 使用 `127.0.0.1:5549`。从旧版带样本升级时，先执行 45 份旧迁移并写入 3 条合成材料及有限的来源、回执、事件、排序和运营状态，之后新增执行 38 份迁移。冷安装执行 83 份，两种方式重复执行均新增 0 份，旧样本逐表逐列比对一致。22 份会删除旧能力或修改运营数据的上游 SQL 由 SHA256 锁定并单独记入保留账本。详见 [迁移兼容与样本复核](CORESCOPE_AIHOT_MIGRATION_20261122.md)。

隔离工作树的 `.data/rehearsal/http-final.json`、`.data/rehearsal/worker-evidence.json`、`.data/rehearsal/sample-heat.json` 和 `.data/corescope-upgrade-rehearsal/rehearsal-result.json` 保存安全检查结果。运行配置、数据库和本地测试文件保留在私有数据目录。通过 `npm run typecheck` 和 `npm run build -w @aihot/web` 可复查构建。

本地预览使用 `http://127.0.0.1:18780`，在隔离 worktree 运行 Web 与 API，显式指定端口 18780/18781 和数据目录。复验时载入 `.data/corescope-upgrade-rehearsal/synthetic.env`，仅使用 5549 的合成库。管理员登录需要单独的合成会话密钥。演练 worker 已验证心跳及调度，可独立启动验证；正式 Windows 启动入口继续管理正式实例。

正式 CoreScope 仍运行旧版本。此次没有读取或迁移正式库，没有重配置 V2、BirdClaw 或全局 Node。验收结论限于上述定向套件和合成站点，完整后端套件没有取得全绿结果。真实数据的升级耗时、锁窗口、磁盘需求、备份恢复和真实供应商验收待正式部署前独立验证。
