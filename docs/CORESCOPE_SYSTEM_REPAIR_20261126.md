# 2026-11-26 系统排查修复

本次针对热点恢复后的系统排查结果，保持 CoreScope 的来源身份、参与方式、全文许可、五维评分、双评分与发布门槛、48 小时最新 2000 条处理范围及现有预算开关。V2、BirdClaw 和其他 checkout 不在修改范围。没有批量重评分、扩大历史处理窗口或释放未知回执。

## 应用修复

- 结构化提示词补齐 `scope`、`fact.evidence`、`fact.conditions` 和当前动作/综合稿的判断要求；保留通信领域词表和标准阶段约束。旧回执的兼容默认值保留，不伪造历史证据。现有提示词展开测试验证实际请求的合同。
- 事件综述只要求当前 schema 消费的 `title` 与 `digest`，不再购买被忽略的 `latest`。公开最新进展继续读取真实报道。
- 日报没有事件时，若窗口内仍有等待归组的精选候选，保留阻塞而不写成平静期。正常无入选事件但已有判断的空刊仍允许；没有任何已判断材料仍拒绝空刊。自动日报补刊限定最近七个到期日，旧缺刊保留为缺口，避免每半小时无限失败；显式补刊接口保留。
- 既有空刊可用带原因和修订号 CAS 的 `correctDailyNotice` 更正异常说明；原截止时间、条目和历史版本保留。晚确认内容按真实公开时间进入后续刊期，不倒填旧刊。
- 普通、私密、重复、恢复、摘要及看门狗通知只在返回 `sent` 后记为已送达；`disabled` 与 `pending` 不消耗送达状态。未曾尝试的私密通知恢复后静默关闭，已尝试的通知重用原身份。
- Dajiala `20001` 余额拒绝进入原共享上游暂停；认证错误准确分类。已暂停的 provider 到期只允许一个探针进入，避免等待任务同时请求 Jina。复用原 15 分钟冷却及服务锁，不改变用户次数预算或未知回执保护。
- 复用原有固定恢复许可，增加最多三篇的 `source-acceptance`：只接收明确授权的公开编辑来源新材料，冻结 URL、来源配置、原日期和修订，创建后 30 分钟内激活；未知付费回执不重放。正常提取产生的新修订沿原许可接续。该许可不授予预算、精选、热度或全文展示权，不扩大旧正文恢复许可的范围。

## 原站入口

同一批公开原站材料按改动前后比较，修复 Intel AI、Anthropic Research、Goodfire、LlamaIndex、Mastra 的列表选择器，以及 Orange 英文新闻室、Qoder 博客和 OpenAI misalignment reports 的官方迁址及日期选择器。保留原 ID、来源种类、参与方式、日期条件与许可。Qoder 只取明确发布时间；OpenAI 只取 `First posted`，不取事故、发现或更新时间。未确认日期不补成今天。

正式配置应用使用原审计升级器。受创建记录保护的 Qoder 需先核查审计与当前配置，再通过正式管理员接口只修改已核实的 config，保留现有采集间隔。HTTP 200 或解析候选数不等于新材料已入库或公开；正式结果以逐源回执和文章版本验收为准。

其他网络、登录、私网地址保护、非 RSS/不相干页面及上游账户拒绝继续如实保留。没有认证绕过、关闭 SSRF 检查、充值或切换付费供应商。

## 本机日常备份

新增显式 `DB_BACKUP_LOCAL_DIR`，沿用唯一 worker 的 `ops.backup` 每天北京时间 04:10 任务。Windows 使用项目便携 PostgreSQL 和系统 tar，无需安装全局 PostgreSQL。数据库归档可读性、附件包可列出及 SHA-256 清单分别记录；本机已验证与远程已上传分开表示。

本机按成功清单保留最近三份完整代次，不按 dump、附件分别淘汰；失败部分文件不会挤掉完整副本，旧无清单备份不归本规则删除。目录不能放入附件目录。新目标目录限制为当前用户、SYSTEM 和管理员。当前本机目标为独立目录，不能替代异盘或远程容灾。完整恢复验证与单纯列出归档分开记录。

## Windows 托管与查询

真实复测中，备份结束后仍有页面超时。确认原计划任务沿用 Windows 默认 Priority 7，PostgreSQL、API、网页和 worker 继承低于正常的 CPU、低 I/O 与低内存优先级；正式库当时有长时间 `DataFileRead`/`BufferIo` 等待，隔离恢复库正常响应。任务定义现在显式使用 Priority 6（正常 CPU、正常 I/O、中等内存优先级）。只在完整用户、项目目录、执行动作和恢复策略匹配后升级本项目原 Priority 7，其他被改写的优先级仍拒绝。现有进程必须完整托管重启才继承；不把只重载应用或静态任务定义变更说成已修复运行性能。优先级含义见 [Microsoft 官方说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-priority-settingstype-element)。

Provider 告警查询改为按服务与模型一次汇总最近成功时间，避免对每条失败重复扫描成功历史；保持 NULL 模型、相同时间戳、不同模型和历史未恢复错误的原有判定。真实全量性能仍以重启后的同口径结果为准，不用计划 cost 或空结果子集替代实际时延证据。
