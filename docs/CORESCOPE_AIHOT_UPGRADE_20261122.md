## 适配内容

- 使用上游新版站点、模块注册、公开读接口和分析发布管线。保留 CoreScope 品牌、资源目录、核心网与 AI 的分类和主题。模型榜通过 CoreScope 模块接入网页、公开接口和定时计算。
- 继续使用 CoreScope 来源配置。第一方标记独立于信源等级，后台可继续编辑。正常公开需要领域相关与有效文案，精选还经过新版事件身份与新增价值判定。人工清空分数、填 0 与移除覆盖分别保留明确语义。后台保留密码、可选飞书登录及反向代理会话检查。
- 沿用 Bird 水位和续页、逐源参与方式、公众号缓存、原站正文路由、文章失败缓存、供应商回执、预算开关、近期队列和固定恢复批次。补发和已接收结果复用仍经过原回执及队列。
- Windows 启动最低要求更新为 Node.js 24.22.1，演练使用独立 Node.js 24.22.3。

## 迁移演练

隔离 PostgreSQL 使用 `127.0.0.1:5549`。从旧版带样本升级时，先执行 45 份旧迁移并写入 3 条合成材料及有限的来源、回执、事件、排序和运营状态，之后新增执行 38 份迁移。冷安装执行 83 份，两种方式重复执行均新增 0 份，旧样本逐表逐列比对一致。22 份会删除旧能力或修改运营数据的上游 SQL 由 SHA256 锁定并单独记入保留账本。详见 [迁移兼容与样本复核](CORESCOPE_AIHOT_MIGRATION_20261122.md)。

## 7 天数据副本的备份与目录回归

本轮继续使用 11 月 15 日 23:13 至 11 月 22 日 23:13（北京时间）的既有副本。验收脚本从该副本建立独立的备份输入库，在其中添加一个嵌套上传文件和一张带数据库引用的反馈截图。运行实际备份程序生成同一时间戳的数据库归档和附件包，恢复到空数据库及空文件目录。在 Windows 上显式使用系统原生 `tar.exe`，避免 Git 自带的 GNU tar 将 `C:` 识别为远程主机。

对比 29 张复制表的行数和逐行内容指纹，52,786 条文章、52,246 条发布记录、5,132 个事件均一致。两份附件的字节一致，恢复后的后台读取函数可以打开反馈截图。由恢复库启动的独立站点通过 32 项冒烟检查，并在精选、全部动态、热点和主题接口返回数据。当前演练站点上的 8 组实数检查和 MCP 合同检查均通过。备份介质为本地磁盘，真实对象存储上传未纳入本轮。

目录失败源自测试在 React Router 初次恢复页面滚动位置之前开始设置滚动值。修正后的用例从已就绪的精选页进入文章，按键前确认焦点、目录边界和正文滚动位置。WebKit 连续通过 15 次，Chromium 对照通过。边界按键不会滚动正文，目录内部仍能用 `PageDown` 滚动。7 天副本中的公开条目使用摘要模式，长目录键盘用例使用合成正文。

Windows 备份专项 15/15，前端全量 78/78，后端独立套件 299/299，V2 导出离线样本 26/26。类型检查、构建和迁移在线安全检查通过。

11 月 23 日完成后端全套回归，原始结果为 1,613 项中 1,513 通过、93 失败、6 取消、1 跳过。8 个文件因 Windows 回收 PID 导致测试库重名，在独立库补跑 35 项，34 项通过，1 项涉及旧测试对第一方标记的预期。其余失败涉及正文封面过滤、旧正文回执的续处理、来源转为编辑模式后的补处理、架构约束以及旧 X 和停机测试的等待超时。全套后端仍待通过，详细结果见 `repair-full-backend-final.log` 和 `repair-backend-*-supplement.log`。

逐项结果保存在演练目录 `.data/rehearsal/` 的 `backup-restore-7d-evidence.json`、`repair-restored-preview.json`、`repair-preview-verification.log` 和 `backup-windows-fixed4.log`。原 7 天副本的内容指纹复核一致。正式版、V2 和 BirdClaw 本轮继续独立运行。
