## 出口、来源身份和资源目录的修正

- 公开 HTTP 采集和探测统一经过 `guardedFetch`。独立 `.env` 现已配置有效 `EGRESS_PROXY_URL`；Hugging Face、Mistral、Import AI 在同一出口取得有效 RSS。每次探测仍保留实际网络路径、HTTP 状态、解析条数、日期和样例，HTTP 200 本身不构成接入成功。
- Qwen 原入口曾指向 ifanr 全站 feed，已替换为官网公开 JSON 接口，验证 40 条真实文章、原始日期和正文。Tencent Cloud、AutoGPT、DeepSeek、Intel、ZTE 改用验证过的官网接口或列表，拒绝把另一出版商的入口当作其官方新闻。
- 华为云采用有真实日期的社区技术博客列表；社区作者不能因此被标为厂商一手公告。已识别为同一出版商的多个入口仍沿用出版商分组，不能重复增加热点独立主体数。
- `v2-source-3335` 的旧中继给出的是搜狗搜索链接，缺少可确认的原文与作者身份。其 `bridgeIntakeUrlPrefixes=[]` 严格拒绝新桥接材料，目录保留待修正；准确的新智元公众号由 `v2-source-6834` 的只读缓存入口覆盖。不能仅按名字把两个入口静默合并。
- 原始订阅凭据和不透明订阅路径不进入公开 profile 或审计文件。需要私有入口的来源保留受限桥接，不能换成随意选取的公共 feed。

8 项已验证资源范围：Intel Community 公共博客记录、Frontend Focus 当前期刊 RSS、Hugging Face 最新创建模型、PyPI 全站更新元数据、npm AI 关键词搜索、GitLab `machine-learning` 公共项目、vLLM 官方容器标签、已配置小宇宙播客的节目记录。GitLab 的 `topic=ai` 实测为空，改用明确的 `machine-learning` 主题；Docker 只观察官方 `vllm/vllm-openai`，不是监听整个 Docker Hub。容器标签的原始推送时间表示资源更新时间，不伪装成首次发布日期。10 项均在资源目录单独展示范围、状态及限制，不声称专业精选或完整覆盖全站。

## 可重跑的验证与应用

在项目根目录执行：

```powershell
# 只访问公开入口及已授权只读公众号缓存，不调用模型或付费提供商
node --env-file=.env scripts/corescope-source-probe.ts
# 只显示复核结果，不改 profile、审计文件或增量进度
node --env-file=.env scripts/corescope-source-probe.ts --ids=v2-source-183,v2-source-106 --no-write
# 中断后的增量进度保存在忽略 Git 的 .data/qa/source-admission-progress.json
node --env-file=.env scripts/corescope-source-probe.ts --resume
# 只复核指定 canonical ID，或限制来源数
node --env-file=.env scripts/corescope-source-probe.ts --ids=v2-source-45,rss-mistral
node --env-file=.env scripts/corescope-source-probe.ts --limit=20
```

探测最多并发 4 个来源，单次公开 HTTP 请求超时 15 秒；复核已接入的来源时使用其当前 native adapter，不会退回旧的错误 feed。脚本保留解析及失败证据，不运行采集 worker、不写 V2、不调用模型。默认会更新本项目 profile 和审计文件，因此应先审阅 Git diff，再应用接入配置；`--no-write` 只显示结果。它不会自动修改正式库。官网特殊接口的补充验证也需保留独立证据及原验证时间，不能将旧证据改写成今日成功。

source pack 生成、正式库 `--dry-run` / `--apply` 和安全停启顺序见 `CORESCOPE_V2_BRIDGE.md`、`CORESCOPE_LOCAL.md`。**本节不宣称 2026-10-12 的正式库升级和完整运行验收已完成**；后续应记录升级回执、实际 source 状态、最近新增、分析积压和发布结果。

## 历史：2026-10-04 产出差距判断

以下解释对应当时的 13 个原生 RSS 配置。其覆盖和出口缺口已由 10 月 12 日迁移补充；开源与线上来源名单差异、模型预算、公开门槛及质量评测边界仍然成立。

1. **采集覆盖未随目录数量扩大。** 161 个启用来源依赖 V2 产出；CoreScope 目前只有 13 个来源自主抓取。V2 的官网解析、公众号 CLI 等规则没有因为目录导入而迁入。
2. **开源示例不等于线上信源名单。** [上游 README](https://github.com/KKKKhazix/AIHOT#说在前面) 明确说明只提供 18 个公开海外示范来源，不包含 AIHOT 自己的信源名单和运营数据。复用引擎仍需接入真实采集依赖。
3. **网络连接失败减少输入。** Hugging Face、Mistral、Import AI 在实际 `guardedFetch` 客户端中发生连接超时；另一条使用执行环境代理的直连探测能返回有效 RSS。当前证据指向采集客户端的出口差异，不能据此认定源站失效。没有在本次审计中修改代理配置。
4. **分析吞吐受预算限制。** LLM 上限为每分钟 20 次、每小时 180 次、滚动 24 小时 800 次请求。预筛、两次评分、写作与归组会分别调用模型；800 次请求不等于 800 篇新闻，过午夜也不会立即重置。预算与失败重试都由付费回执层管理。02:45 复核时，最近 24 小时已有 720 次 LLM 回执，均收到响应、没有重试；其中评分 253 次、预筛 155 次、结构提取 127 次，其余用于摘要、理解、归组、综述等。停机期间旧请求逐步退出窗口，因此“36 条保留预算错误”不表示复核时额度仍完全耗尽。恢复 worker 后可以继续按原预算处理，没有人为调高额度。
5. **入库、公开和精选是不同阶段。** 首页分层门槛为 T1 60、T1.5 65、T2 76；全部新闻也需要通过公开条件。热点要求最近 48 小时内同事件有至少两个独立参与主体，重复抓取或同机构多个入口不会增加主体数。来源数量增加不必然增加精选或热点。
6. **连续运行曾中断。** 用户确认关闭过启动窗口；之后网页、API、worker、bridge 和 PostgreSQL 均不在运行，未找到主动 Stop 记录。这一启动生命周期问题单独修复，修复结果与验收边界见 `CORESCOPE_STARTUP_FIX.md`。

本次没有同素材的人工作业或模型对照评测，不能把这些运行证据解释为行业分析质量本身不如 AIHOT。

验收应按有效抓取率、最近 24 小时新增、等待分析时长、公开转化、精选转化与热点多主体覆盖衡量。上述来源迁移是后续工作，本次没有通过降低精选门槛或提高付费预算来制造产出。
