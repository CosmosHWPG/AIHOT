# CoreScope 前端与主题语义检查

日期：2026-10-03。检查源码、生产构建与配置；不调用模型，不操作完整系统服务。

## 验证结果

- 前端 typecheck 和生产构建通过。
- 32 项 web 测试通过，包括生产 SSR 交叉筛选回归：页面确实向 API 传递 `tag=核心网&topic=ai`，搜索保留两个条件，AI 全景主题必须仅配置 `AI` 标签。
- 前端源码、客户端/SSR 构建及配置入口共 197 个文件，与本机 `.env` 中 8 个敏感值逐字比对，无实际值匹配。构建内没有 `.env` 文件，没有 source map。检查只输出计数和匹配文件名，未输出配置值。
- 公司主题使用 `entity:<id>` 实际主体标记；不按显示标签或顺带提及匹配。
- AI 商业、AI 评测、AI 安全主题只使用相应专用标签，避免 OR 匹配纳入整个 AI 领域或通信评测、安全内容。

## 筛选语义

`全部` 清除领域 tag 与 topic；`核心网` 和 `AI` 各使用单个明确领域标签。`交叉` 由两个独立 SQL 条件组成，要求文章同时具有核心网与 AI 标签。没有用多个 topicTags 实现交叉，因为 topicTags 内部采用 OR。

切换领域保留类别、频道、搜索，清除页码与游标；移动搜索入口、搜索表单、列表 canonical 和时间线后续请求保留 topic。主题目录的领域入口筛选目录项，通用主题可以涵盖两个领域，页面明确提示这一点。

## 验证范围与限制

文件扫描验证当前配置的敏感值未进入当前前端产物，不代替整个服务端安全审计。HTTP 对私有文件的访问保护、管理员权限及服务运行状态由完整系统验收核对。

领域筛选依赖已发布文章的领域标签。模型写作标签可能覆盖结构阶段标签，因此后端归一化需要保留两个阶段显式领域标记，并按行业包的 `DOMAIN_TAG_RULES` 补齐独占领域；不得从公司、信源或通用技术标签推断。更改主题配置后需重新 seed，并刷新读取缓存。

本次没有用生产数据库验证交叉筛选的实际文章集合，完整系统运行协调者负责 API 集合断言与浏览器截图。没有把空主题填成示例新闻，也没有按客户端过滤重算服务器页数。
